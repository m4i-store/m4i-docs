# m4i_rental — Admin Creator

> دليل [V4 Review Build](source-status.md). الأمر الافتراضي `/rentaladmin`، والصلاحية `m4i.rental.admin`. السيرفر يعيد التحقق من الصلاحية عند القراءة والنسخ والحفظ والحذف ومراجعة الأداء.

## إنشاء الفرع

افتح `/rentaladmin` واضغط إنشاء مكتب. أدخل اسماً وID فريداً، ثم اضبط موقع البناية والموظف. يمكن إدخال `x, y, z, heading` أو `vector4(...)`؛ `vector3(...)` مقبول في الواجهة ويستعمل اتجاهاً افتراضياً صفر. النتيجة المرسلة للسيرفر كائن رقمي `{ x, y, z, h }` وليست نص Lua ينفذ.

معرف الفرع لا يتغير من نموذج تعديل الفرع الموجود. لكل حفظ revision؛ إذا عدل admin آخر نفس النسخة، ارجع للائحة وأعد تحميل آخر بيانات بدلاً من الكتابة فوقها.

## الكاميرا الحرة والمعاينة

قف على قدميك واستعمل زر الكاميرا بجانب البناية أو الموظف أو موقف السيارة. الشخصية تبقى ثابتة، والموديل المعروض شفاف ومحلي فقط. تظهر عناصر المسودة الأخرى لتنسيق المواضع؛ لا يراها اللاعبون الآخرون ولا تكتب إلى SQL حتى الحفظ النهائي.

| التحكم | الوظيفة |
| --- | --- |
| WASD والماوس | حركة الكاميرا وتوجيهها. |
| Q / Z | الصعود والنزول. |
| Shift | حركة أسرع. |
| عجلة الماوس | قرب أو بعد عنصر المعاينة. |
| السهمان يمين/يسار | دوران العنصر. |
| PageUp / PageDown | تعديل الارتفاع. |
| H | تبديل الالتقاط إلى السطح. |
| Enter | تأكيد الموضع والرجوع للنموذج. |
| Esc | إلغاء جلسة وضع العنصر؛ إلغاء المسودة يتم من النموذج. |

عند تحريك البناية بالكاميرا يتبع الموظف موضعه النسبي. عند تعديل vector يدوياً راجع موضع الموظف بنفسك. تبقى الأشباح إلى نهاية المسودة، ويعيد الإلغاء الكاميرا وتحكم الشخصية ويزيلها. الوفاة أو توقف المورد يجب اختبار تنظيفهما ضمن [بوابة الاختبار](testing.md).

## مواقف السيارات

أضف 2–10 مواقف، وكل موقف له heading مستقل. أدخل vector أو اضبطه بكاميرا وسيارة معاينة. `blista` مجرد موديل معاينة عندما الكاتالوغ فارغ؛ لا يصبح سيارة قابلة للكراء تلقائياً.

احترم حدود [الإعدادات](configuration.md)، واختر أرضاً مسطحة خارج البناية وغير متداخلة مع حركة الشارع. فراغ المركز لا يكفي لإثبات أن سيارة طويلة لا تصطدم بالحائط؛ جرب كل موديل فعلياً.

## كاتالوغ الفرع

لكل سيارة أدخل الاسم المعروض، spawn model، رابط HTTPS لصورتها، وثمن الساعة كعدد صحيح موجب. المدة الأخرى تحسب من هذا السعر. اللون يختاره اللاعب عند الشراء.

يمكن استيراد كاتالوغ من فرع آخر. العملية تنسخ الأسماء والموديلات والصور والأسعار إلى **مسودة مستقلة**؛ تعديلها لا يغير المصدر. حد السيارات 20 ولا يسمح بتكرار model داخل الفرع.

## الحفظ والنشر والإلغاء

الزرع الأول فقط استثناء يحتوي مواقف وكتالوغاً فارغين. **أي حفظ عادي، حتى لفرع غير منشور، يحتاج 2–10 مواقف و1–20 سيارة ومواضع صالحة.** التعطيل لا يتيح حفظ نموذج غير مكتمل.

تفعيل النشر يتيح المبيعات. إلغاء المسودة لا يكتب SQL. تعطيل فرع محفوظ يبقي البناية والعقود المؤداة، لكنه يمنع الشراء والتجديد المالي الجديد من كاتالوغه. يمكن لصاحب عقد نشيط استرجاع سيارته المفقودة وفق تحقق المحل.

حذف فرع عنده عقد `pending` أو `active` أو `repossessing` أو `cleanup` يرفض. عطله وانتظر إكمال العقود والاسترجاع قبل الحذف. لا تحذف صفوف SQL يدوياً لتجاوز هذا الشرط.

## مراجعة الأداء

لوحة الإدارة تعرض عمليات `review` للمطابقة مع ledger الحقيقي. لا تختَر نتيجة مالية بالتخمين. [دليل الأداء والاسترجاع](payments.md) يشرح الفرق بين اقتطاع غير مؤكد واسترجاع غير مؤكد؛ القرار يحتاج سبباً مسجلاً، وتوجه العملية إلى الرد والإلغاء وليس منح سيارة مجانية.

المصدر: `client/creator.lua` و`web/app.js` و`shared/domain.lua` ودوال `saveSite` و`deleteSite` و`resolvePayment` في `server/rental.lua`، وفق [لقطة المصدر](source-status.md).
