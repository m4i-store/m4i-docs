# m4i_rental — مقدمة

نظام كراء سيارات بوقت حقيقي مع موظف استقبال، واجهة اختيار السيارة واللون والمدة، أداء من الكاش والبنك، تجديد، تسجيل مؤقت، وإدارة مكاتب الكراء داخل اللعبة.

> **الحالة: Review Build، وليست نسخة معتمدة للإنتاج.** يشرح هذا القسم حزمة `m4i_rental_v4_REVIEW_BUILD.zip` التي تحمل `version '4.0.0'` في manifest. لا يعني نشر التوثيق أن كود V4 اندمج في مستودع السكريبت أو اجتاز اختبار FiveM. اقرأ [حالة النسخة ومصادر التوثيق](source-status.md) قبل تطبيق الأوامر.

## ما الذي يشمله القسم؟

واجهة اللاعب تعرض الاسم والصورة والثمن للساعة، اللون، الدقائق أو الساعات أو الأيام الحقيقية، ورصيد cash وbank والمجموع. السيرفر يحسب الثمن ويخزن تاريخ الانتهاء. التجديد يضيف مدة إلى نهاية العقد النشيط، ورفضه لا يلغي الوقت المؤدى عنه.

الإدارة تستعمل `/rentaladmin` لإنشاء مكتب بمعرف فريد، ضبط البناية والموظف والمواقف بواسطة إحداثيات أو كاميرا حرة ومعاينات شفافة، وإعداد كاتالوغ مستقل. الحد الحالي هو 2–10 مواقف و1–20 سيارة لكل مكتب.

المكتب هو CarRent V3 الموجود، مع سقف وبابين أماميين وباب خدمة مستقلين وإضاءة. **هو building shell وليس MLO بنظام rooms/portals.** لا تعيد حزمة V4 تصدير ملفات الموديل ولا تحول الصور الفنية إلى نموذج مطابق لها. البناية والأبواب والموظف محليون عند كل عميل؛ سيارات الكراء ينشئها السيرفر كعناصر شبكية.

## حدود التكامل

```text
m4i_rental -> m4i_bridge -> مزود الهوية والفلوس وقاعدة البيانات
```

الحزمة الموثقة تستعمل عقد Bridge v4، ولا تستدعي QBCore أو ESX أو m4i_core مباشرة من منطق الكراء. اختلاف مزودي الهوية والفلوس يحتاج اختباراً على البيئة المنشورة؛ توافق العقد ليس إثباتاً بأن كل مزود اختبر فعلياً.

التسجيل والمفاتيح مؤقتان داخل سجل الكراء. لا تضاف ملكية دائمة إلى garage أو MDT أو inventory تلقائياً. تكامل تلك الموارد يتم بواسطة [الصادرات والأحداث](exports.md).
